# Train the v1.1.0 Adaptive Styles research baseline

This pipeline is implemented and runs on the local RTX 3050 6 GB. It trains a
small student from preferences generated by a frozen aesthetic teacher. These
are **pseudo-labels**, not human ground truth or proof of improvement in Apple Photos.

## Run it

From `research/adaptive-styles`, using the Python environment that has CUDA PyTorch:

```powershell
python train.py run --max-images 1000 --epochs 20 --batch-size 8
```

This one command prepares working copies, creates labels and trains the student.
The default dataset is `data/processed/baseline-v1`; the run is
`outputs/baseline-v1`. A prepared dataset freezes its photo list and split. Repeating
`run` reuses it, finishes missing labels and resumes the last completed epoch.
Increase `--epochs` above the completed epoch count when continuing training.
To include newly downloaded photos, choose new `--data` and `--run` directories.

The first labeling run downloads about 350 MB of verified OpenAI CLIP weights and
a small LAION head into `outputs/cache/teacher/`. The student downloads the roughly
10 MB torchvision pretrained checkpoint to PyTorch's cache if missing. Labeling
is the slower stage; completed labels are reused. Candidate images are rendered
in memory, so the default run does not write tens of thousands of full images.
Do not run multiple labeling/training processes against the same dataset/run directory.

Current local Python already has the training libraries and CUDA support. For a
new environment, install a compatible **CUDA** PyTorch/torchvision pair using the
[official installer](https://pytorch.org/get-started/locally/), then:

```powershell
python -m pip install -e ".[train]"
python -c "import torch; print(torch.__version__, torch.cuda.is_available())"
```

`uv sync --extra train` installs optional dependencies but does not by itself
guarantee a CUDA-enabled wheel. Select the correct environment/kernel. The existing
machine was verified with Python 3.10, torch 2.2.2+cu121 and torchvision 0.17.2+cu121;
the research project also supports Python 3.12. Keep NumPy below 2 for this tested
older PyTorch stack.

## What the pipeline actually learns

1. `prepare` reads `data/Apple/`, `data/raw/inputs/` and `data/raw/references/`.
   It applies EXIF orientation and converts embedded ICC profiles to sRGB. Untagged
   images are assumed sRGB and flagged. Originals remain unchanged; working PNGs
   have a longest side of 512 px. Known collages, very small images, low-chroma
   candidates and exact duplicates are excluded with reasons in the manifest.
2. It groups close full-frame duplicates conservatively using a perceptual hash
   plus aspect ratio, then splits groups 80/10/10. This heuristic cannot identify
   every crop or burst. For known related photos, copy `groups.example.csv` to
   `data/metadata/groups.csv` and add workspace-relative `path,group_id` rows **before
   preparation**. Review the split before claiming independent evaluation.
3. `label` renders 55 edits across the app's 14 color Styles. The candidate grid
   includes an exact unchanged Standard image, parameter variations and reduced
   Palette variants. Style defaults/profiles are read from the app's JavaScript;
   Python renderer output is checked against the actual JavaScript in tests.
4. The frozen [LAION aesthetic V1 predictor](https://github.com/LAION-AI/aesthetic-predictor)
   scores normalized [OpenAI CLIP ViT-B/32](https://github.com/openai/CLIP) image
   embeddings. Published/pinned artifact hashes are verified before loading.
   Scores receive small content-change and added-clipping penalties. If the winning
   edit beats unchanged Standard by less than 0.03, the conservative label is Standard.
   Full-frame letterboxing is an explicit adaptation of the teacher input transform;
   the scores are a ranking proxy, not a calibrated measure of human taste.
5. The student uses MobileNetV3-Small's pretrained features, a 128-dimensional head,
   14 Style logits and 14 sets of bounded Tone/Color/Palette parameters. Standard's
   Palette is fixed at 1 to match the app contract. It learns soft Style preferences
   and probability-weighted parameter targets.

These downloaded photographs serve as the **inputs to candidate preference
generation**. No separate model is fitted to an Apple-only reference distribution.
The student learns the teacher's preferred app-renderable edits on these photos;
it does not recover the edits originally used to make the reference photos.
Beautiful source images may correctly receive an unchanged recommendation.

The SDR renderer approximates Stylio's current display rendering. It is not Apple's
native image-processing pipeline or an HDR training/evaluation system. Native Photos
renders, skin tones and real user preferences still need independent validation.
Teacher/data terms remain separate from the code license; do not infer distribution
rights for a public model from successful local research training.

## Run individual stages and review labels

```powershell
python train.py prepare --max-images 1000
python train.py label --batch-size 8
python train.py review --limit 50
```

Open `outputs/label-review/index.html`. Each sheet shows unchanged Standard, the
teacher choice and top candidates with their IDs. Edit the accompanying
`overrides.csv`: set `candidate_id` to your choice, leave it blank to keep the teacher
choice, or set `accept=0` to exclude an image. The review generator never overwrites
an existing override file. Pass it explicitly when training:

```powershell
python train.py train --run outputs/reviewed-v1 --overrides outputs/label-review/overrides.csv
```

Changed labels or images require a new training run. Resume checks dataset/image
hashes, supervision and important optimizer settings to prevent silent mixing.
Create review sets from training data for tuning. Avoid changing test labels or
choosing settings after looking at the held-out test results.

## Outputs, evaluation and mobile export

Runs save `best.pt`, `last.pt`, `run-config.json`, `baselines.json` and `metrics.jsonl`.
The first epoch trains the heads; subsequent epochs fine-tune the last three feature
blocks. BatchNorm statistics remain frozen for small batches. Defaults use batch 8,
gradient accumulation 4, AdamW, CUDA FP16 AMP and Windows-friendly `num_workers=0`.

```powershell
python train.py evaluate --checkpoint outputs/baseline-v1/best.pt
python train.py predict --checkpoint outputs/baseline-v1/best.pt --image path/to/photo.jpg
python train.py export --checkpoint outputs/baseline-v1/best.pt
```

Evaluation defaults to validation and reports teacher/reviewer label agreement and
target-parameter MAE, with majority/Standard baselines stored in the run folder.
Use `--split test` only for final evaluation. These metrics do not establish that
users prefer the output. Prediction confidence is uncalibrated label-agreement
softmax, not a probability that a photo will look beautiful.

Exports contain an FP32 ONNX and `model.json` describing normalization, letterboxing,
Style IDs, parameters and artifact hashes. Export runs ONNX Runtime parity checks
for dynamic batch sizes. The smoke model is about 4 MB. Teacher assets are not
included. This is a new research inference contract; the released app's embedding
models are not replaced automatically. Browser/iPhone latency, quantization and
native color quality require their own integration checks.

## Small verification run

```powershell
python train.py run --max-images 24 --data outputs/smoke-data --run outputs/smoke-run --epochs 2 --batch-size 4 --accumulation 2 --max-batches 2
```

This checks execution and memory only. Two training batches per epoch cannot assess
aesthetic quality. `--max-batches` and `--no-pretrained` are smoke-test options; do
not use them for a real baseline. If VRAM is tight, reduce `--batch-size` to 4 or 2.
Use `--device cpu` for functional debugging, with much slower teacher scoring.

the real-app renderer parity check).
